# Languages (i18n)

The UI shows in 17 languages (list and endonyms in `core/src/languages.ts`). The language is a persisted setting (`language`, `''` = never chosen). The webview detects a default from `navigator.language`. Decision record: [ROADMAP → Onboarding and 17 languages](../catavasia/ROADMAP.md#onboarding-and-17-languages-featonboarding-owner-request-2026-10-12).

## Layout

```
webview-ui/src/i18n/
  core.ts            defineNamespace, Translation, interpolate (do not edit per feature)
  dictionaries.ts    loads every <namespace>/<language>.ts by glob (no registry to edit)
  languageStore.ts   current language, <html lang> and dir
  languageSync.ts    settingsLoaded -> store, chooseLanguage() -> persist
  useT.ts            the React hook
  <namespace>/en.ts  the typed source of keys, one folder per namespace
  <namespace>/<code>.ts   one file per other language
```

One namespace belongs to one slice, so parallel work never edits the same file.

## Add a string

1. Add the key to `<namespace>/en.ts` (inside `messages`).
2. Add the same key to the other 16 files of that namespace. The type `Translation<typeof ns>` fails the build when a key is missing or extra.
3. Use it:

```tsx
import { common } from '../i18n/common/en.js';
import { useT } from '../i18n/useT.js';

const t = useT(common);
t('language'); // plain
t('greeting', { name: cat.name }); // message "Hello {name}"
```

Outside React, call `translate(ns, key, getLanguage(), params)` from `i18n/dictionaries.js` and `i18n/languageStore.js`.

Rules: one sentence per key. Never build a sentence from pieces (word order differs). No plural logic: write one key per form. Keep domain terms (`eROAS`, `CPI`) exact. A key missing at run time falls back to English, then to the key.

## Add a namespace

Create `webview-ui/src/i18n/<name>/en.ts`:

```ts
import { defineNamespace } from '../core.js';

export const messages = { title: 'Hello' } as const;
export const myNs = defineNamespace('myNs', messages);
```

The folder name must equal the name in `defineNamespace`. A non-English file looks like this:

```ts
import type { Translation } from '../core.js';
import type { myNs } from './en.js';

export const messages: Translation<typeof myNs> = { title: 'Привет' };
```

## Add a language

Add one entry to `LANGUAGES` in `core/src/languages.ts` (code, endonym, rtl). Add `<code>.ts` to every namespace folder. `webview-ui/test/i18n.test.ts` checks the key sets.

## Settings, server and fonts

- `language` and `onboardingDone` live in `config.json` (per namespace). Messages: `setLanguage`, `setOnboardingDone`, and two fields on `settingsLoaded`. Server code: `server/src/onboardingState.ts`.
- The server reads the same `language` setting for narrator lines and cat bubbles (`getLanguage(adapter)`).
- Fonts: `--font-pixel` lists FS Pixel Sans first, then `--font-script-fallback` (system fonts for CJK, Indic, Arabic scripts). No new pixel font.
- Do not set `left`/`right` for layout that must flip. Use logical Tailwind classes (`ms-*`, `me-*`, `ps-*`, `pe-*`, `text-start`) so `dir="rtl"` works.

## Help chat contract

`webview-ui/src/onboarding/HelpChat.tsx` exports `HelpChat` with a fixed props interface: `{ open: boolean; onClose(): void; context?: 'onboarding' | 'settings' }`. The onboarding flow mounts it. The help chat work implements its body and owns the `helpChat` namespace.
